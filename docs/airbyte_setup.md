# RetailPulse: Airbyte ELT Ingestion Guide

This document provides complete, verified instructions for installing and configuring **Airbyte Open Source (OSS)** to replicate transactional retail sales records from **PostgreSQL** (`retail_source.public.orders`) into **Google BigQuery** (`raw_retail.orders`).

---

## PART A — Airbyte Installation & Lifecycle Management

> [!IMPORTANT]
> **Architecture Update: Docker Compose Sunsetted**
> Airbyte has officially **sunsetted and deprecated Docker Compose deployments**. Airbyte now runs natively on Kubernetes.
> To run Airbyte locally on Windows without complex Kubernetes management, Airbyte provides **`abctl`** (Airbyte Command-Line Tool). Under the hood, `abctl` spins up a lightweight `kind` (Kubernetes in Docker) cluster and installs Airbyte via Helm charts.

### 1. Prerequisites
- **Docker Desktop for Windows:** Installed and running.
- **Hardware Resources:** Minimum 8 GB RAM and 4 CPUs allocated in Docker Desktop settings.
- If running with lower resources, the `--low-resource-mode` flag must be used.

---

### 2. Windows Installation Options

#### Method 1: Using WSL2 Ubuntu (Recommended by Airbyte)
Running `abctl` inside WSL2 avoids Windows-specific shell formatting and execution quirks.
```bash
# Inside your WSL2 Ubuntu terminal:
curl -LsfS https://get.airbyte.com | bash -

# Launch Airbyte locally
abctl local install --low-resource-mode
```

#### Method 2: Native Windows PowerShell Installation
If you prefer running natively in PowerShell:
1. Download the latest Windows binary release from GitHub:
   [https://github.com/airbytehq/abctl/releases](https://github.com/airbytehq/abctl/releases)
   *(Download `abctl_windows_amd64.tar.gz` or `.zip`).*
2. Extract `abctl.exe` and place it in your User directory or a folder in your System `PATH` (e.g., `C:\Users\Swapnaja\AppData\Local\agy\bin` or `C:\Program Files`).
3. Verify installation in PowerShell:
   ```powershell
   abctl --version
   ```
4. Install and run Airbyte locally:
   ```powershell
   abctl local install --low-resource-mode
   ```

---

### 3. Accessing the Airbyte UI & Credentials

During the initial installation, `abctl` generates a secure random password for the `admin` user.

To retrieve your generated credentials:
```powershell
abctl local credentials
```
Output will display:
- **URL:** `http://localhost:8000`
- **Username:** `admin` (or your email)
- **Password:** `<auto-generated-random-password>`

Open your browser, navigate to **`http://localhost:8000`**, and sign in.

## PART B — PostgreSQL Source Configuration

Inside the Airbyte UI, navigate to **Sources** &rarr; **+ New Source** &rarr; Select **Postgres**.

### CRITICAL NETWORKING RULE: Host Resolution
> [!CAUTION]
> **DO NOT USE `localhost` OR `127.0.0.1`**
> Airbyte connectors execute inside isolated Docker containers / Kubernetes pods. To the container, `localhost` means the container itself, NOT your Windows host machine.
> - **For Windows Host / Docker Desktop:** Set Host to **`host.docker.internal`**.
> - Docker Desktop automatically resolves `host.docker.internal` to the host gateway IP address.

### Connection Parameters:
| Setting | Value | Notes |
| :--- | :--- | :--- |
| **Source Name** | `Postgres_RetailSource` | Descriptive identifier |
| **Host** | `host.docker.internal` | Routes from container to host port 5432 |
| **Port** | `5432` | Standard PostgreSQL port |
| **Database** | `retail_source` | Database created in Phase 2 |
| **Schemas** | `public` | Schema holding `orders` |
| **User** | `postgres` | Configured user |
| **Password** | `<your_postgres_password>` | Password from your `.env` |
| **SSL Mode** | `disable` | For local development |
| **Replication Method** | `Standard (Scan Changes via SELECT)` | Ideal for 500-record batch demo |

Click **Set up source** and wait for the green **Testing connection** checkmark.

## PART C — Google BigQuery Destination Configuration

In the Airbyte UI, navigate to **Destinations** &rarr; **+ New Destination** &rarr; Select **BigQuery**.

### Configuration Parameters:
| Setting | Value | Notes |
| :--- | :--- | :--- |
| **Destination Name** | `BigQuery_RawRetail` | Descriptive identifier |
| **Project ID** | `<YOUR_GCP_PROJECT_ID>` | Your actual Google Cloud Project ID |
| **Dataset Location** | `US` (or your chosen region) | Must match `raw_retail` dataset region |
| **Default Dataset ID** | `raw_retail` | Target dataset created in Phase 3 |
| **Authentication** | `Service Account Key JSON` | Paste contents of `keys/gcp_service_account.json` |
| **Loading Method** | `Standard (Batched Inserts)` | Direct insert; requires no GCS bucket ($0.00 cost) |

> [!WARNING]
> While pasting the service account JSON into the Airbyte UI text box is necessary for Airbyte to authenticate, **never commit this JSON file or paste it into git repositories**.

Click **Set up destination** and verify the green test confirmation.

## PART D — Connection & Synchronization Setup

1. In Airbyte, click **Connections** &rarr; **+ New Connection**.
2. Select **Postgres_RetailSource** as the Source.
3. Select **BigQuery_RawRetail** as the Destination.
4. **Streams Configuration:**
   - Locate the stream `public.orders`.
   - Ensure the toggle switch is **Enabled**.
   - If other tables appear, leave them **Disabled**.
5. **Sync Mode:**
   - Select **`Full Refresh | Overwrite`**.
6. **Schedule Type:**
   - Select **Manual** (Or leave on 24 hours). Member 2 will trigger it programmatically via Airflow.

### Architectural Explanation: Why `Full Refresh | Overwrite`?
- **Behavior on First Run:** Extracts all 500 records from `retail_source.public.orders` and writes them into `raw_retail.orders`.
- **Behavior on Subsequent Runs:** Airbyte writes newly ingested records to a temporary table in BigQuery and performs an atomic swap when complete. Old records are overwritten, completely eliminating duplicate records.
- **Viva Rationale:** In a 500-row batch demonstration, `Full Refresh | Overwrite` guarantees idempotency and absolute consistency without requiring incremental tracking timestamps or CDC log parsing.

7. Click **Set up connection**, then click **Sync Now**.
8. Wait for the sync status to change from **Running** to **Succeeded**.

## Troubleshooting Common Errors

### 1. `Connection refused (Connection to host.docker.internal:5432 refused)`
- **Fix:** Ensure PostgreSQL is running and port `5432` is bound to `0.0.0.0` or all interfaces, not just `127.0.0.1`.
- If running PostgreSQL in Docker: Ensure port mapping is `-p 5432:5432`.
- Verify Windows Defender Firewall is not blocking incoming connections on port 5432 from Docker.

### 2. `Access denied / Permission Denied (BigQuery)`
- **Fix:** Ensure the service account has `roles/bigquery.jobUser` on the project and `roles/bigquery.dataEditor` on the `raw_retail` dataset (see [bigquery_permissions.md](file:///c:/Users/Swapnaja/OneDrive/Desktop/RetailPulse/docs/bigquery_permissions.md)).

### 3. `abctl local install hangs or times out`
- **Fix:** Docker Desktop may be starved of resources. Increase allocated RAM to 8 GB in Docker Desktop Settings &rarr; Resources, or use the `--low-resource-mode` flag.
