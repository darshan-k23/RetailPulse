- **Inquiry:** *"Which product generated the highest revenue?"*
- **Target Table:** `analytics_retail.sales_by_product`
- **SQL Executed:**
  ```sql
  SELECT
      product,
      total_orders,
      total_quantity,
      total_revenue
  FROM
      `analytics_retail.sales_by_product`

      total_revenue DESC
  LIMIT 1;
  ```

## 5. Issues Encountered & Technical Remediations

| Issue | Root Cause | Engineering Solution |
| :--- | :--- | :--- |
| **1. Potential Airflow failure when Airbyte connection UUID is not yet bound** | In local microprojects, students may run Airflow before finishing Airbyte UI setup. | Built `check_airbyte_sync_mode` (BranchPythonOperator) that smoothly routes to acceptable simplified mode if `AIRBYTE_CONNECTION_ID` is blank. |
| **2. Conversational prompt keyword collision** | Natural language queries like *"Show all laptop transactions in south region"* contained both `"all"` and `"laptop"`. | Updated regex/keyword extractor to check for multi-attribute entity extraction (`product` + `region`) first, safely routing to `analytics_retail.stg_orders`. |
| **3. Streamlit cloud credentials dependency during offline viva** | If college network blocks GCP ports or trial credits lapse, live BigQuery queries throw exceptions. | Implemented a dual-mode `WarehouseService` that falls back to a reconciled local analytics engine matching dbt transformations down to the exact rupee. |
| **4. Airflow Docker paths vs. Host paths** | Mounting dbt inside Airflow container requires path translation. | Dynamically resolved `DBT_PROJECT_DIR` checking `/opt/airflow/dbt` when running in Docker and relative host paths when running locally. |
